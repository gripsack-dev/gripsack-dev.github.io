your whole environment, in one bag.

keep your packages and dotfiles in one repo, reproduce them on another machine, and roll the entire setup back when something goes wrong.

start with one dotfile

you don't have to rebuild your life. brew or apt keep handling binaries; gripsack starts with ~/.config, and package fetching is adopted later, tool by tool. the ownership question is the whole game:

adopting helix — every step is a design principle
$ grip init my-env && cd my-env
$ cp -r ~/.config/helix configs/   # your config becomes the payload
$ # modules/helix.py: config = { "configs/helix": tree("~/.config/helix") }
$ grip apply
error[E109]: ~/.config/helix/config.toml exists (not deployed by gripsack) — kept
  | pass --take-over to adopt it
$ grip apply --take-over   # explicit handover — never a silent clobber
$ # edit the file in your repo, apply, break something…
$ grip rollback              # the whole setup is back. one flip.

four ownership modes, because real dotfiles are messy: owned — a read-only symlink for disciplined tools; tracked_copy — a real copy for apps that rewrite their own config (Zed), with your edits detected, never overwritten; merge — a managed block inside a shared file like .bashrc; template — rendered from per-host vars. the full adopting guide.

a module

myenv/modules/helix — python and typescript, both typed, same IR 
from gripsack import module, github_release, symlink, tracked_copy

helix = module(
    "helix",
    fetch=github_release(
        repo="helix-editor/helix",
        asset="helix-{version}-x86_64-linux.tar.xz",
    ),
    install={"bin/hx": symlink("~/.local/bin/hx")},
    config={
        "config.toml": tracked_copy("~/.config/helix/config.toml"),
        "languages.toml": tracked_copy("~/.config/helix/languages.toml"),
    },
)
import { module, githubRelease, symlink, trackedCopy } from "@gripsack/core";

module("helix", {
  fetch: githubRelease({
    repo: "helix-editor/helix",
    asset: "helix-{version}-x86_64-linux.tar.xz",
  }),
  install: { "bin/hx": symlink("~/.local/bin/hx") },
  config: {
    "config.toml": trackedCopy("~/.config/helix/config.toml"),
    "languages.toml": trackedCopy("~/.config/helix/languages.toml"),
  },
});

the frontends are libraries — pip install gripsack or npm i @gripsack/core — and fully typed: pyright or tsc gives you autocomplete, inline errors, and refactors, because a module is just typed code. evaluation emits IR (JSON); the Rust core only ever consumes IR. the typescript frontend evaluates through bun, provisioned and pinned like everything else.

errors that point at your code

every IR node carries a span back to the line that emitted it
$ grip plan
error[E101]: module "helix" depends on unknown module "nvim"
  --> modules/helix.py:4:7
   |
 4 | helix = module("helix", fetch=..., depends=[dep("nvim")])
   |       ^ dependency declared here

structured diagnostics with stable codes and source snippets — and because the passes are library functions over span-labeled IR, an LSP is a protocol shim, not new analysis.

what it does

01

dotfiles, first-class

your config files, managed per file: read-only links for disciplined tools, copies that never overwrite your edits, managed blocks in shared files. per-host variants pick files by machine facts — no templating language.

tracked_copy(…)
02

any source

install tools from anywhere: github releases, brew bottles, git, tarballs, conda — and anything with a weirder download dance as a small plugin. every byte is hash-checked. the fetchers.

github_release(…)brew(…)
03

generations

every apply is a complete new generation; switching is one atomic flip, so nothing is ever half-deployed. roll back by flipping to any previous one. a no-op apply creates nothing.

grip rollback
04

lockfiles, not sandboxes

inputs pinned by URL and content hash, per host. reproducible inputs, deliberately not hermetic builds — that guarantee is Nix's, honestly theirs.

grip update

how it works

[01]

describe

modules are typed Python in your repo: sources, build steps, config files, ownership.

[02]

evaluate

modules evaluate to IR — pure data. host facts & tags resolve here, nowhere else.

[03]

lock

the resolved plan pins URLs and content hashes per host. reproducible inputs — deliberately not hermetic builds.

[04]

build

fetchers and builders run as a parallel DAG, N = cores, into hash-addressed store paths.

[05]

activate

one atomic symlink flip. dotfiles deployed per ownership mode.

[06]

roll back

flip current back, and every managed destination follows — symlinks, tracked copies, merge blocks, rendered templates. that's the whole mechanism.
