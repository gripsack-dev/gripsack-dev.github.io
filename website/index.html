01 / How it works

Declare. Plan.
Apply. Keep a way back.

Setting up a machine is usually a pile of commands nobody can replay. Gripsack turns it into a file you can read, review and roll back.

Declare

Write gripsack.ts: packages from release archives or Conda, dotfiles with explicit ownership, environments, Docker services, tasks.

gripsack.ts

Plan

Evaluation runs in a sandbox with no network and no environment. You see every file that would change and every source you are about to trust.

grip plan

Apply

One transaction: prior state is journaled before any write, each destination is re-checked for your own edits, then one atomic rename makes the new generation current.

grip apply

Keep a way back

Every applied state is a retained generation. Rollback reselects one: retained bytes, nothing rebuilt, your local edits preserved.

grip rollback

02 / What you declare

One graph.
Six kinds of output.

Bring the user-space pieces you manage into one catalog. Leave the operating system to its own package manager.

Packages

Pin a release archive, solve a coherent Conda environment or import a Pixi lock. Nothing installs into a global prefix; the lockfile is the only source of versions.

Environments

grip run and grip shell put selected packages on your path for one command or one shell, without touching your dotfiles.

Profiles & dotfiles

Symlink, tracked copy or one managed block in a shared file: you choose how much of each file gripsack owns. Your edits are never silently overwritten.

Docker services

Digest-pinned PostgreSQL, Redis or any image, on loopback ports with explicit health checks. grip down keeps the volumes.

Tasks & checks

Named commands with prerequisites, locks and postconditions. Validate a config file before it is ever written to its destination.

Schedules & sharing

systemd user timers that run the same tasks on a calendar, and signed package bundles you can hand to another machine or registry.

03 / Safety

Proved where it matters.
Honest everywhere else.

Gripsack is built in rings. The pure decisions at the center are plain Rust, translated to Lean 4 and proved there; each ring outward is checked in a cheaper way and trusts only the rings inside it.

  • Commit classificationAfter a crash, the next run decides Committed, Uncommitted or Ambiguous from the current, previous and target generation, and never guesses. Proved in Lean since 0.52.
  • Garbage collectionGC refuses while recovery is pending, prunes only the oldest generations beyond your retention and never deletes the current one or anything a root names. Proved.
  • Journal publicationA record becomes durable only in the order stage → sync file → publish name → sync directory; a mutation needs a durable run marker and a durable entry. Proved.
  • Crash anywhere, then recoverThe apply, rollback, recover and GC machines are next: a proof that any crash followed by recovery leaves every destination at its prior bytes, its intended bytes, or something you wrote yourself.
  • The filesystem and the worldAtomic rename, fsync durability, SHA-256 identity and a single lifecycle writer are stated assumptions, fault-tested rather than proved. Docker, systemd, Deno and your own hooks are outside every proof.
{anim:rings}

What is and is not claimed. The proofs are over the exact Rust that ships, use only Lean's standard axioms and run as a release gate next to the test suites. They cover decisions, not the operating system, and not the effects of your own hooks, tasks or containers. Read the full guarantee list →

04 / Quick start

One file.
One useful change.

A file-only workspace needs no package download and no Docker. Three commands later you have a generation you can roll back to.

Save this as gripsack.ts in its own repository (or run grip init my-env for a scaffold):

gripsack.ts
import {
  defineWorkspace, file, literalText, managedBlock, profile, workspace,
} from "@gripsack/core";

const dotfiles = profile("dotfiles", {
  files: [file({
    content: literalText("export EDITOR=vi\n"),
    destination: managedBlock("~/.profile", "gripsack-editor"),
  })],
});

export default defineWorkspace(() => workspace({ outputs: [dotfiles] }));

From declaration to deployment

After installing grip, approve the source when prompted, then:

  1. 01

    Validate the workspace

    grip check
  2. 02

    Read the proposed changes

    grip plan dotfiles
  3. 03

    Apply when you are ready

    grip apply dotfiles

The rest of ~/.profile stays yours: a managed block owns only the section between its markers. grip generations lists what you can return to; grip rollback returns to it.

05 / Three more shapes

Same file.
Different workspaces.

Each tab is the complete gripsack.ts from its guide, run as part of the release checks. Pick one.

gripsack.ts · packages
import {
  defineWorkspace, environment, githubRelease, pkg, provider,
  targetPlatform, workspace,
} from "@gripsack/core";

const target = targetPlatform({ os: "linux", arch: "x86_64", abi: "musl" });
const ripgrep = pkg("ripgrep", {
  producer: provider(githubRelease({
    repo: "BurntSushi/ripgrep",
    asset: "ripgrep-{version.bare}-x86_64-unknown-linux-musl.tar.gz",
  })),
  archiveRoot: { kind: "single_directory" },
  commands: { rg: "rg" },
  target,
  layout: { kind: "relocatable" },
});
const search = environment("search", { packages: ["ripgrep"], target });

export default defineWorkspace(() => workspace({ outputs: [ripgrep, search] }));

A release archive becomes a package; an environment puts rg on the path for one command. Packages guide →

grip update
grip build ripgrep
grip run --env search -- rg --version
gripsack.ts · service
import {
  defineWorkspace, exec, lit, service, task, workspace,
} from "@gripsack/core";

const postgres = service("postgres", {
  image: "docker.io/library/postgres@sha256:979bccfde35445db618c65107d27d08c6c21339d8dc3ad4c830c6633947be0e4",
  ports: [{ address: "127.0.0.1", host: 55432, container: 5432 }],
  volumes: [{ name: "gripsack-guide-postgres18", target: "/var/lib/postgresql" }],
  env: {
    POSTGRES_USER: { kind: "literal", value: "app" },
    POSTGRES_DB: { kind: "literal", value: "app" },
    POSTGRES_PASSWORD: { kind: "inherited", name: "GRIPSACK_POSTGRES_PASSWORD" },
  },
  health: {
    kind: "command",
    argv: ["pg_isready", "-U", "app", "-d", "app"],
    interval_seconds: 2,
    timeout_seconds: 2,
    retries: 30,
  },
});
const databaseReady = task("database-ready", {
  services: ["postgres"],
  steps: [exec({ argv: [lit("/usr/bin/printf"), lit("postgres is healthy\\n")] })],
});

export default defineWorkspace(() => workspace({ outputs: [postgres, databaseReady] }));

A digest-pinned PostgreSQL on loopback, a health check, and a task that requires it to be healthy. The password is inherited from your environment, never written down. Services guide →

: "${GRIPSACK_POSTGRES_PASSWORD:?}"
grip up postgres
grip task run database-ready --closed-stdin

gripsack.ts · task
import {
  bash, conda, defineWorkspace, environment, lit, packageCommand,
  pkg, provider, targetPlatform, task, workspace,
} from "@gripsack/core";

const target = targetPlatform({ os: "linux", arch: "x86_64", abi: "gnu" });
const shell = pkg("shell", {
  producer: provider(conda.environment({
    channels: ["conda-forge"],
    packages: { bash: "*" },
    systemRequirements: {
      libc: { family: "glibc", version: "2.28" },
      linux: "4.18",
    },
  })),
  commands: { bash: "bin/bash" },
  target,
  layout: { kind: "prefix_materialized" },
});
const dev = environment("dev", { packages: ["shell"], target });
const greet = task("greet", {
  environment: "dev",
  steps: [
    bash`printf '%s\n' "$MESSAGE"`
      .interpreter(packageCommand("shell", "bash"))
      .env("MESSAGE", lit("two words"))
      .build(),
  ],
});
export default defineWorkspace(() => workspace({ outputs: [shell, dev, greet] }));

A literal Bash body with a pinned interpreter from Conda and a typed environment binding; no JavaScript interpolation into shell. Tasks guide →

grip update
grip task run greet --closed-stdin
