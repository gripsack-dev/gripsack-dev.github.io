how it works

1

describe

modules are typed Python in your repo: sources, build steps, config files, ownership.

2

evaluate

modules evaluate to IR — pure data. host facts & tags resolve here, nowhere else.

3

lock

the resolved plan pins URLs and content hashes per host. reproducible, no sandbox.

4

build

fetchers and builders run as a DAG into hash-addressed store paths.

5

activate

one atomic symlink flip. dotfiles deployed per ownership mode.

6

roll back

flip current to any previous generation. that's the whole mechanism.

a module

myenv/modules/helix — sketch; the api is not final 
from gripsack import module, github_release, symlink, tracked_copy

helix = module(
    "helix",
    fetch=github_release(
        repo="helix-editor/helix",
        asset="helix-{version}-x86_64-linux.tar.xz",
    ),
    install={"bin/hx": symlink("~/.local/bin/hx")},
    config={
        "config.toml": tracked_copy("~/.config/helix/config.toml"),
        "languages.toml": tracked_copy("~/.config/helix/languages.toml"),
    },
)
import { module, githubRelease, symlink, trackedCopy } from "@gripsack/core";

module("helix", {
  fetch: githubRelease({
    repo: "helix-editor/helix",
    asset: "helix-{version}-x86_64-linux.tar.xz",
  }),
  install: { "bin/hx": symlink("~/.local/bin/hx") },
  config: {
    "config.toml": trackedCopy("~/.config/helix/config.toml"),
    "languages.toml": trackedCopy("~/.config/helix/languages.toml"),
  },
});

the frontends are libraries — pip install gripsack or npm i @gripsack/core — and fully typed: pyright or tsc gives you autocomplete, inline errors, and refactors, because a module is just typed code. evaluation emits IR (JSON); the Rust core only ever consumes IR.

errors that point at your code

every IR node carries a span back to the line that emitted it
$ grip plan
error[E101]: module "helix" depends on unknown module "nvim"
  --> modules/helix.py:4:7
   |
 4 | helix = module("helix", fetch=..., depends=[dep("nvim")])
   |       ^ dependency declared here

structured diagnostics with stable codes and source snippets — and because the passes are library functions over span-labeled IR, an LSP is a protocol shim, not new analysis.

what it does

[01]

one module

fetch, build, install, config — one typed Python module declares the whole lifecycle, from github release to deployed dotfile. anything else arrives as a gripfetch-* plugin.

module(…)gripfetch-*
[02]

store + generations

builds land in a content-addressed store; every apply is a new generation and activation is one atomic flip. rollback flips it back — a no-op apply creates nothing.

grip applygrip rollback
[03]

never clobbers

store-owned symlinks, tracked copies with drift detection — and a foreign path is refused, not overwritten, unless you say --take-over.

tracked_copy(…)--take-over
[04]

lockfile-pinned

URLs and content hashes pinned per host; facts and tags resolve at eval, so one repo serves the fedora laptop and the macos desktop. reproducible, no sandbox.

grip updatetags = ["gui"]
[05]

errors with spans

eval-time diagnostics carry a span back to the line of your module that emitted them — stable codes, source snippets, no guessing.

error[E101]
[06]

proxy-friendly

works behind corporate proxies: HTTPS_PROXY honored, system CA roots trusted, and GRIPSACK_PYTHON when you must bring your own interpreter.

HTTPS_PROXYGRIPSACK_PYTHON
