one small example →workspace guide

one workspace, named outputs

A workspace exports the things you use. Packages and environments serve development commands; profiles deploy your personal files through the generation transaction. Start with a single managed block:

gripsack.ts
import {
  defineWorkspace, file, literalText, managedBlock, profile, workspace,
} from "@gripsack/core";

const dotfiles = profile("dotfiles", {
  files: [file({
    content: literalText("export EDITOR=vi\n"),
    destination: managedBlock("~/.profile", "gripsack-editor"),
  })],
});

export default defineWorkspace(() => workspace({ outputs: [dotfiles] }));

Save as gripsack.ts in a repository. Use matching core and SDK bytes; review the source and policy when prompted.

grip check
grip plan dotfiles
grip apply dotfiles

Review the plan before applying. grip generations lists retained generations; grip rollback restores a previous managed state. Read the ownership and recovery boundaries.

install deliberately

The signed release selected for this site is v. Its installer checks the signed local-qualification manifest before installation.

curl -fsSL https://gripsack.dev/install.sh | sh -s -- --version {version}

grip self-update independently selects the latest signed release. Qualification and site binding.

Reviewer prerelease: 0.47.0 is unsigned and unverified. Use its manual installation instructions and matching SDK archive to try the workspace APIs shown here. It is not the authenticated installer selection; npm/crates publication is not implied.

Capture-glob exclusions and the --focus view require core/SDK 0.48; they are not in 0.47. Check the release records for available artifacts and qualification evidence.

go deeper when you need to

  • Workspace and profile migration — move from legacy modules without losing ownership.
  • Adopt existing dotfiles — choose links, tracked copies or managed blocks.
  • Packages and development environments — build, run and launch tools.
  • Safety and recovery — review source, preserve drift and recover interrupted changes.
  • SDK reference on GitHub — complete declarations and advanced contracts at the signed release source.
  • Release scope and roadmap · changelog.

Mutable tools use reviewed source re-capture, not locked mutable overlays: deploy a repository tree with trackedCopyTo, let the tool edit its copy, then copy intended changes back to the repository, exclude caches, review and approve the source, and apply. The lockfile never snapshots a live destination.
