Documentation for core/SDK v0.48.0. Release and verification scope.

Compare

Gripsack 0.48 manages user-space packages, environments and configuration, not the operating system. New authoring uses a root gripsack.ts workspace; legacy host/module repositories remain supported. You can leave system packages with apt or another manager and adopt only the files you choose.

These are scope comparisons, not claims that another tool cannot be extended. Nix is the stronger general-purpose reproducible-build system. Gripsack's captured inputs and lockfiles do not make legacy shell steps hermetic or undo arbitrary external effects. Workspace recipes use an explicit production contract; the qualified owned-worker route is Linux x86_64 with Docker, not an unconditional “no daemon” promise.

Gripsack's supported hosts are Linux and WSL2 on x86_64, not macOS or native Windows. File-only profiles need no build worker; provider-backed packages and retained outputs can also avoid a worker. A file-only adoption can be incremental, but taking ownership still requires a deliberate decision. Rollback requires retained history and respects drift; late activation failure is not an automatic whole-machine undo. See adoption, workspace migration, and safety.

Release status

Core 0.48 is the public latest release, unsigned, with 17 practical local gates and 96 persistence partitions passed. TLC, TLAPS and Verus remain explicitly unqualified; these results are not formal qualification or completion of the original roadmap. Core 0.47 remains an unsigned, unverified prerelease.

Use the release's manual archive installation instructions: 0.48 has no npm or crates.io publication, and the signed core installer/updater still fails closed. The documentation website is built locally and does not require signed release artifacts; its availability is not release-authentication evidence.
